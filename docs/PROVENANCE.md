# Material provenance

## Implementation and protocol data

The code lives in `src/korail_api/`. Its architecture separates schema-directed requests and decoding, generated value objects, session state, queue admission, HTTP transport and token serialization.

Protocol contracts describe public names, signatures, constructor defaults, wire fields, endpoint paths and serialization order. Synthetic input/output fixtures exercise those contracts. Decoder observations under `tools/validation/observations/` are development-only test data, excluded from release artifacts.

## Vendor message data

The vendor error catalog was imported from `assets/error_json.json` in a locally available application artifact identified as version `7.0.10`. Its resource SHA-256 is `7b7998f2582217aba20e58a722b3640a6ef3a2751d9816aaf2f78cfc97c74d00`. The importer records 12,430 codes and 19,381 translations. The version label comes from the local artifact context; the artifact's delivery origin was not independently authenticated. The APK and extracted raw vendor files are not distributed. The catalog text remains third-party material; independent extraction does not make its text maintainer-owned or supply a redistribution license.

`tools/catalog/import_messages.py` can regenerate the catalog from a separately supplied local artifact. It reads a ZIP resource and never executes application code. Secrets and application binaries are not bundled.

## Dependencies and technical references

Runtime dependencies are installed separately and retain their own licenses. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) records the direct dependencies, vendor-data rights and protocol references. The maintainer licenses only material they have authority to license.

Selected search/session components of pykorail, korail2 and SRT were inspected at pinned revisions. The source references are recorded in `tools/reports/related-projects.md`; no implementation from those projects is bundled or required as a runtime dependency.

The ordinary schedule endpoint's `201` compatibility marker and protocol version `250722001` were informed by the documented observations in [devgyurak/pykorail](https://github.com/devgyurak/pykorail) at revision `5e485fd56a2482e741fde14d87dea8f381352f43` and verified independently with an anonymous read-only request. The marker is not a native, device-bound or cryptographic signature; its acceptance can change. This observation was used for the ordinary schedule endpoint only, and no pykorail source code is bundled. The referenced project has its own noncommercial license.

## Software declaration and ordinary-reservation compatibility (2026-11-02)

`security/declaration.py` and `services/compatibility.py` are implementations authored for this repository using wire-format observations documented by pykorail at revision `030576a6b41d874f35ebdf6b2d68ed76e70a1af7`. Its [protocol evidence](https://github.com/devgyurak/pykorail/blob/030576a6b41d874f35ebdf6b2d68ed76e70a1af7/docs/protocol-evidence-7.0.10.json) describes the software declaration envelope, framing, byte order, digest operations and word encoding for application version 7.0.10. No pykorail implementation or dependency is bundled. Its source and documentation retain their own license; this implementation does not claim ownership of their expression or of vendor protocol parameters.

The public static codec parameter is a build constant, not an account credential or installation secret. The software-state declaration uses `es=288904575606514493`, `kl=990094375841594426` and `ec=978212327729758430` from those observations. These values do not prove attestation, hardware support, enrollment or server acceptance. The default board is empty rather than an invented board identifier; callers may provide accurate facts. Device identity is synthetic unless explicitly supplied, and is excluded from representations.

`tests/fixtures/declaration-vectors.json` records SHA-256 digests of the reported emulator outputs for nonce 0 and 5, together with their artificial inputs. The reported library hash is `a884a4971dda8b7a1b05f90d331631ea95f65028dc51aba55e2699ac90ed7129`; the emulator was not rerun for this change. `tests/fixtures/reservation-compatibility.json` contains 17 synthetic ordinary-reservation queries independently intercepted from the installed pykorail implementation before transmission. Inputs cover adult counts and supported passenger mixtures; no account data, real device identity, response capture or credentials are included. Assertions compare complete queries, not values generated by the new implementation itself.

The compatibility profile uses GET on the existing ordinary reservation endpoint, wire version `250722001`, explicit blank fields and sorted passenger groups. It is selected once before transmission, only for the declaration provider and ordinary immediate reservations without designated seats. Existing queue admission and transaction-outcome protections remain active. This change includes no live login, reservation, cancellation or payment validation. The earlier observation that a short `201` marker worked for one read endpoint is not evidence that all token contents or all endpoints are accepted.
